# Cats in Menubar 그림 가이드 (그림 만들 때·넣을 때 먼저 읽기)

새 고양이 그림을 그리거나 앱에 넣는 사람(GPT, Claude 포함)은 이 문서를 먼저 읽는다.
그림이 바뀌면 이 문서도 같이 고친다. 예전 버전의 그림과 작업 기록은 git 기록에만 있다(2026-10-29 정리).

## 1. 앱이 읽는 그림

| 파일 | 내용 |
|---|---|
| `app/macos/Resources/Cats/sheets/<색>.png` | 색마다 시트 한 장. 8열×16행 = 128칸, 칸 102×68px, 전체 816×1088px. 쓰지 않는 칸은 완전히 투명. |
| `app/macos/Resources/Cats/sheets/<색>.json` | 칸 크기, 머리 기준 `headX`, 바닥선 `ground`, `pixelsPerPoint`(2), 걷기 보폭 `walkStride`, 그림 수 `frameCount`, 행동 목차 `animations`. |

- 지금 있는 색: **orange, white, black, silver, cream**. tuxedo, calico, siamese는 시트가 생길 때까지 orange 그림을 쓴다(초안은 `design/coat-drafts/`, 7절).
- 시트는 **성묘가 2배 화면에서 보이는 크기 그대로**(2px = 1pt)다. 더 큰 원본을 런타임에 줄이지 않는다.
- 빌드(`tools/prepare_assets.swift`)는 시트를 칸으로 자르기만 한다. 포즈 하나하나를 다시 자르거나 늘이거나 줄이지 않는다. 대신 칸마다 발 위치·좌우 끝을 재서 `sheet.json`에 적고, 1배/2배 화면 × 고양이 크기 3가지(0.64/0.82/1.0) 메뉴바용 시트 6장을 미리 만든다.

## 2. 행동 목차 (`animations`)

코드에는 칸 번호가 없다. 앱은 아래 이름으로만 칸을 찾는다. 그림을 옮기거나 장 수를 바꾸면 json의 목차만 고친다. 칸 하나는 한 행동에만 속한다.

| 이름 | 지금 칸 | 재생 |
|---|---|---|
| stand | 0 | 서기. 크기·그림체의 기준 칸 |
| idle | 1–3 | 서서 꼬리 흔들기, 1→2→3→2 |
| walk | 4–19 | 걷기 16장. 걸은 거리 9.6pt(성묘)마다 한 바퀴, 기본 6pt/s에서 1.6초 |
| run | 20–27 | 달리기. 29pt마다 한 바퀴 |
| turn | 28–31 | 방향 전환, 장당 0.09초 뒤 좌우 반전 |
| sitDown → sit | 32–33 → 34 | 서기→앉기 |
| loafDown → loaf | 35–36 → 37 | 앉기→식빵 |
| sleepDown → sleep | 38–40 → 41–42 | 식빵→잠, 잠은 41↔42 호흡 |
| groom | 43–46 | 그루밍 |
| stretch | 47–51 | 기지개(서기→내려가기→늘이기→올라오기→서기) |
| yawn | 52–53 | 앉아서 하품 |
| crouch | 54–55 | 웅크림(54가 사냥 대기 자세) |
| creep | 56–59 | 낮게 걷기 |
| wiggle | 60–61 | 엉덩이 흔들기 |
| pounce | 62–65 | 덮치기·집으로 폴짝 |
| bat | 66–67 | 공 치기 |
| held | 68–69 | 들어 올렸을 때 |

칸 70–127은 새 그림용으로 비워 둔다. 행동별 시간·확률·연결은 `design/cat-behaviors.docx`에 있다(그 문서의 번호는 예전 62장 번호이고, 생성 스크립트가 목차로 바꿔 그림을 가져온다).

## 3. 그림 규칙

- **크기 기준은 stand(0번)의 머리와 눈.** 모든 자세에서 머리·눈 크기가 같아야 한다. 자세 때문에 키나 길이가 달라지는 것은 괜찮다.
- **머리 기준선:** 옆을 보는 자세는 눈이 칸의 `headX`(x=80) 근처에 오게 놓는다. 걷기·달리기는 가로 1px 안.
- **바닥:** 발이 `ground`(y=62) 근처에 오게 그린다. 몇 px 어긋나도 빌드가 칸마다 발을 바닥선에 붙인다. 달리기와 덮치기는 묶음 전체를 한 번에 내려서 공중 장은 뜬 채로 남는다.
- **그림체:** stand와 같은 외곽선 굵기·색, 단순한 명암, 크림색 발끝, 분홍 귀·코. 색마다 같은 포즈·같은 실루엣이어야 한다(색만 다름).
- **연결:** 기준 자세(허브)는 서기, 앉기, 식빵, 잠, 웅크림. 각 동작의 첫 장과 마지막 장은 해당 허브와 같은 크기·위치로 그린다.
  - 걷기·달리기·방향 전환·기지개: 서기에서 시작해 서기로 끝
  - 그루밍·하품: 앉기에서 시작해 앉기로 끝
  - 낮게 걷기·엉덩이 흔들기·공 치기: 웅크림에서 시작해 웅크림으로 끝(덮치기는 서기로 끝)
  - 허브 사이는 sitDown, loafDown, sleepDown 연결 그림으로만 간다.
- **느린 걷기:** 네 발을 따로 추적한다. 순서는 왼뒤 → 왼앞 → 오른뒤 → 오른앞. 각 발은 약 75% 접지, 25% 들어 옮기기. 바닥의 발은 몸이 간 만큼 뒤로만 가고, 든 발만 앞으로 온다. 같은 그림을 두 번 넣어 장 수를 채우지 않는다.

## 4. 새 그림 넣는 법

1. 시트를 `sheets/<색>.png`로, 목차를 `sheets/<색>.json`으로 넣는다(형식은 orange와 같게). 8색 이름 중 하나면 빌드가 자동으로 집는다.
2. `zsh tools/test.sh`. 확인하는 것:
   - 모든 행동이 목차에 있고 칸 안에 그림이 있는지, 걷기 칸이 끊기지 않고 이어지는지
   - 걷기·달리기 눈 크기, 가로 위치(1px 안), 그려졌을 때 머리 높이 차이(2pt 미만)
   - 빈 칸이 완전히 투명한지
   - 미리보기 `build/previews/lineup.png`(색×크기), `scenario.png`(걷다가 돌아서는 장면을 실제 크기로)
3. 색을 바꿔 만든 시트는 눈 이외의 어두운 선이 눈 색으로 바뀌지 않았는지 확대해서 본다(black에서 실제로 있었던 문제).

## 5. 알려진 문제

- black은 어두운 메뉴바에서 잘 안 보인다. 필요하면 밝은 테두리를 따로 그린다.
- turn 마지막 칸(31)은 몸이 칸 왼쪽에 있어 돌 때 옆으로 튀는지 실제 화면에서 확인해야 한다.
- pounce 그림은 고양이 충돌 범위보다 조금 넓다.

## 6. Silver·Cream 추가 (2026-10-29, 앱 적용)

- orange의 70개 자세를 기준으로 silver(은회색 줄무늬), cream(연한 크림색 줄무늬) 시트와 동일한 json을 추가했다.
- ImageGen 색상 참고안을 기준으로 정적 RGB 변환했다. 모든 픽셀의 alpha와 프레임 배치는 orange와 동일하며 분홍 귀·코는 유지한다. 런타임 색상 필터는 없다.
- 두 시트를 직접 확인했고, 생성 시 전체 픽셀 alpha 및 동일한 metadata를 검증했다. 전체 test.sh는 로컬 서명 인증서가 없어 빌드 시작 전 중단됐다.

## 7. Tuxedo·Calico·Siamese 초안 — 미적용 (2026-10-29)

- GPT가 위치별 정적 무늬로 만든 세 시트는 **자세마다 무늬가 바뀐다**. 앱은 서기↔걷기↔앉기를 계속 오가므로 무늬가 깜빡이듯 바뀌어 보인다. 그래서 앱에 넣지 않고 `design/coat-drafts/`로 옮겼다. 비교: `design/coat-drafts/inconsistent-markings.png`.
  - tuxedo: 서기(0)·기지개·웅크림은 몸 대부분이 흰색, 걷기·앉기는 몸 대부분이 검정.
  - calico: 얼룩 위치·색이 자세마다 다르고, 귀·머리 주변에 직선(사각) 경계가 보인다. 정면(30)은 얼굴 전체가 검정.
  - siamese: 걷기·앉기는 얼굴이 진한 갈색 마스크인데, 서기(0)·기지개·덮치기·공 치기는 얼굴이 밝다.
- 고칠 때 기준: **같은 고양이로 보이도록 몸 부위별로 무늬를 고정**한다(예: tuxedo는 몸·머리 위·꼬리 검정, 가슴·네 발·주둥이 흰색; siamese는 얼굴 마스크·귀·네 발·꼬리 진한 갈색, 몸 크림색; calico는 몸통 위 얼룩 2–3개의 위치를 모든 자세에서 같게). 서기(0)를 기준으로 70장이 같은 무늬여야 한다. 직선 경계 금지.
- 고친 시트는 `sheets/<색>.png|json`으로 옮기면 바로 적용된다.
