# Cats in Menubar 그림 가이드 (그림 만들 때·넣을 때 먼저 읽기)

새 고양이 그림을 그리거나 앱에 넣는 사람(GPT, Claude 포함)은 이 문서를 먼저 읽는다.
그림이 새로 들어오면 이 문서도 같이 고친다.

---

## 1. 지금 그림이 앱에 들어가는 방식

| 단계 | 어디서 | 내용 |
|---|---|---|
| 원본 | `app/macos/Resources/Cats/<색>.png` | 색마다 1536×1024 시트 한 장(8색: orange, black, white, silver, cream, tuxedo, calico, siamese). 위 18칸 위치는 `layout.json`에 있다. |
| 들어 올린 자세 | `design/held-cats-v1.png` | 3열 × 8행(행 = 색, 열 = 가운데/왼쪽으로 늘어짐/오른쪽으로 늘어짐). |
| 잘라내기 | `tools/prepare_assets.swift` (빌드 때 자동 실행) | 칸마다 가장 큰 그림 덩어리를 잘라 `build/.../Resources/Cats/<색>/<번호>.png`로 저장하고, 머리 위치와 발 높이를 `metadata.json`에 적는다. |
| 크기 | `SpriteAtlas.sourceScale = 24/180` | 원본에서 서 있는 성묘 키 180px이 화면의 24pt가 된다. 고양이 크기 설정(아기/중간/성묘)은 여기에 0.64/0.82/1.0을 곱한다. |
| 그리기 | `SpriteAtlas.swift` | 그림마다 **처음 쓸 때 한 번만** 화면 픽셀 크기로 단계적으로 줄여 저장해 두고, 이후에는 그 작은 그림을 픽셀 격자에 맞춰 그린다. 원본은 고화질로 두면 된다. |
| 어느 장면을 쓸지 | `SpriteAtlas.frameIndex(_:)` | 고양이 행동과 속도를 보고 번호를 고른다. 걷기와 달리기는 걸어간 거리에 맞춰 장을 넘긴다(발이 미끄러지지 않게). |

### 지금 번호표 (색마다 21장)

| 번호 | 장면 | 쓰는 곳 |
|---|---|---|
| 0–5 | 걷기 6장 | 걷기. 멈추면 **4번을 임시 "서 있기"로** 쓴다. |
| 6–11 | 달리기 6장 | 달리기, 쫓기, 집에 가기, 덮치기·폴짝(시간 순). 10번(웅크림)은 사냥과 공 치기 직전 자세로도 쓴다. |
| 12 | 앉기 | 앉기, 공 지켜보기 |
| 13 | 식빵 | 식빵 |
| 14 | 웅크려 자기 | 잠 |
| 15 | 앞으로 기지개 | 기지개 |
| 16 | 그루밍 | 그루밍 |
| 17 | 공 치기(공이 그려져 있음) | 지금은 안 씀(앱이 공을 따로 그림) |
| 18–20 | 매달림: 가운데 / 몸이 왼쪽으로 / 오른쪽으로 | 마우스로 들었을 때 |

## 2. 화면에서 실제로 보이는 크기 (중요)

- 사용자의 모니터 두 대는 **일반(1배) 화면**이다. 성묘가 화면에서 **가로 약 29px, 세로 약 19~24px**로 보인다. 레티나(2배) 화면이면 그 두 배.
- 즉 원본을 **약 7.5배 줄여서** 보여준다. 원본의 7~8px이 화면의 1px이다.

그래서 이렇게 그린다.
1. **실루엣이 먼저다.** 작게 줄였을 때 머리, 귀, 다리, 꼬리 모양만으로 무슨 동작인지 보여야 한다.
2. **테두리는 원본에서 6~8px 이상.** 더 가늘면 줄였을 때 사라진다.
3. **눈은 원본에서 지름 10px 이상**, 주변과 대비가 크게.
4. **가는 줄무늬와 작은 털 디테일은 줄이거나 굵게.** 줄이면 얼룩처럼 뭉개진다.
5. **완성 전에 실제 크기로 줄여서 확인한다**(4장의 확인 방법 참고).

## 3. 지금 그림의 문제 (고쳐야 할 것)

한 장 한 장은 예쁘지만, 연속 동작으로 이어 그린 게 아니라서 화면에서 끊겨 보인다.

- **걷기 6장:** 꼬리 위치가 장마다 제멋대로다(위 → 아래 → 위). 머리 높이, 귀 모양, 몸 길이도 장마다 달라 머리가 떨린다. 다리가 "앞발 닿기 → 지나가기 → 뒷발 닿기" 순서로 이어지지 않는다.
- **달리기 6장:** 몸 높이가 장마다 크게 다르다(바닥에 붙은 장 ↔ 높이 뜬 8번). 꼬리도 순서 없이 바뀐다.
- **연결 그림이 없다:** 앉기 ↔ 서기, 서기 ↔ 눕기, 방향 바꾸기가 순간이동처럼 넘어간다. 지금은 코드로 0.15초 겹쳐서 바꾸는 임시 처리만 했다.
- **서 있기 그림이 없다:** 멈추면 걷기 4번을 임시로 쓴다.
- **사냥 자세 전용 그림이 없다:** 달리기 10번을 빌려 쓴다.

## 4. 새 그림 규칙

### 공통
1. 지금 **오렌지 고양이와 같은 캐릭터, 같은 화풍, 같은 크기**(서 있는 성묘 키 약 180px). 오른쪽을 보는 옆모습. **진짜 투명 배경**(체크무늬, 색 테두리, 그림자, 글자 없음).
2. **한 동작 = 한 장의 가로 띠(strip).** 칸 크기 **256×256px로 모두 같게**, 왼쪽부터 순서대로.
3. **바닥선은 모든 칸에서 위에서 232px.** 서 있는 발바닥이 이 선에 닿는다. 점프처럼 뜨는 장면만 위로 뜬다.
4. 같은 동작 안에서는 **머리 크기, 머리 높이(±2px), 귀 모양, 몸 길이가 같아야 한다.** 움직이는 건 다리, 꼬리, 정해진 만큼의 몸 위아래뿐이다.
5. **꼬리는 이어서 움직인다.** 한 사이클에 한 번 흔들리는 식으로, 장마다 새 꼬리 모양을 만들지 않는다.
6. 반복 동작은 **마지막 장 다음에 첫 장이 바로 이어져야 한다.**
7. 연결 동작은 **첫 장이 시작 자세, 마지막 장이 끝 자세와 똑같다**(예: 서기→앉기는 첫 장 = 서 있기, 마지막 장 = 앉기).
8. **먼저 오렌지만.** 앱에 넣어 확인한 다음 나머지 7색을 같은 포즈로 만든다.

### 파일 이름과 위치
- `app/macos/Resources/Cats/v3/orange/<동작>.png` 에 넣는다. 예: `walk.png`, `run.png`, `stand.png`.
- 지금 쓰는 `orange.png`, `layout.json`, `held-cats-v1.png`는 **새 그림을 앱에 연결할 때까지 지우거나 덮어쓰지 않는다.**
- 새 그림을 앱에 연결하는 코드(`prepare_assets.swift`, `SpriteAtlas.frameIndex`)는 그림이 들어온 뒤 따로 고친다. 그림을 그리는 쪽은 그림 파일과 이 문서의 목록만 맞추면 된다.

### 확인 방법
```bash
xcrun swift tools/onion_strip.swift build/previews/walk-check.png app/macos/Resources/Cats/v3/orange/walk.png 8
```
- 띠를 칸별로 나란히 그리고, 오른쪽에 **모든 칸을 반투명하게 겹친 그림(onion)**을 만든다.
- 겹친 그림에서 **머리, 귀, 몸통이 한 덩어리로 겹쳐 보이고 다리와 꼬리만 퍼져 보이면 합격.** 머리가 여러 개로 번져 보이면 장마다 머리가 흔들리는 것이다.
- 맨 아래 줄에 **실제 화면 크기(1배)로 줄인 그림**도 같이 나온다. 그 크기에서 동작이 읽히는지 본다.

## 6. 그림이 들어온 뒤 코드에서 할 일 (그림 그리는 쪽은 안 해도 됨)

1. `prepare_assets.swift`가 `v3/<색>/<동작>.png` 띠를 칸 단위로 읽게 한다(256px 칸, 바닥선 232px).
2. `SpriteAtlas.frameIndex`를 동작별 띠로 바꾼다. 멈추면 `stand`, 사냥과 공 치기 직전은 `crouch`/`bat`.
3. 동작이 바뀔 때 연결 띠(`stand-to-sit`, `turn` 등)를 먼저 재생하고 넘어가게 한다. 그러면 지금의 0.15초 겹치기 처리는 연결 그림이 없는 경우에만 남긴다.
4. 걷기 장 넘김을 8장 기준으로 바꾼다(걸은 거리 기준은 그대로).
5. `tools/test.sh`의 그림 확인 미리보기에 새 동작을 추가한다.
